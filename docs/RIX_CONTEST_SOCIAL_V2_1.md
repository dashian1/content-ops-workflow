# RIX 工作台 V2.1：AI 平台比赛监控＋多社交平台账号监控

日期：2026-10-12。状态：开发任务书与公开来源核查，不是已运行的监控服务。
仓库：`dashian1/content-ops-workflow`。
依赖文档：同分支的 `docs/RIX_PORTABLE_OPS_V2.md`。

> 本文是 V2 的增量规格：保留 Flask、SQLite、本地工作区、代码/数据/凭证分离、打包恢复、知识审核和真实测试等要求；新增比赛专用模型，并明确 AI 平台与社交平台的接入范围。不得为了新增监控而取消可迁移能力。
>
> 用户目标：在一个工作台发现值得参加的 AI 创作比赛，跟踪截止时间和规则，同时观察多个社交平台上的自有账号、参考创作者及主办方官方账号。

下文平台范围、字段、提醒时间、界面与验收标准属于产品设计。引用 [S] 支持来源入口或接口边界，不代表每个平台现在有比赛、所有比赛已收录、爬虫已经获得许可或已实测。

## 1. 必须拆开的两个模块

| 模块 | 监控对象 | 输出 |
|---|---|---|
| 比赛中心 | AI 软件平台的比赛、创作挑战、短片/海报征集、相关创作者激励 | 比赛卡片、资格与规则、奖金结构、期限提醒、变更记录、参赛进度 |
| 账号监控 | 同一社交平台的多个账号及跨平台账号 | 新作品、可取得的指标变化、发布时间、来源健康与参考内容 |

平台活动不只从官网读取。为每家 AI 平台关联其活动页、官方公告和已核实官方社交账号；官方社交帖子里发现比赛后，继续寻找正式规则和报名入口。

主体区分：`provider` 是 OiiOii/Flova 等 AI 平台；`social_platform` 是抖音/YouTube 等传播平台；`account` 是某平台上的具体账号；`source` 是实际读取的网页、列表、频道或接口。不要用一个 platform 字段混装四种对象。

比赛、抽奖、邀请返利、普通折扣、产品更新、获奖公告、创作者招募分别分类。默认重点是 AI 图片/海报、视频、短片、动画、广告和 MV 创作；应用开发赛、一般编程赛默认归入其他分类，不混进视觉创作比赛推荐。

### 2.3 来源登记规则

`provider_id, name, aliases, homepage_urls, locale_scope, priority, source_urls, source_kind, identity_evidence_url, reviewed_at, discovery_status, connector_status, policy_review_status, enabled`。

公开种子只带公开平台信息，初始 `enabled=false`、`connector_status=not_verified`、`policy_review_status=pending`。只有用户启用且适配器/权限检查通过才自动采集。

来源身份与采集能力独立：`官方来源已核实` 不等于 `提取已测试`，后者也不等于 `定时监控已验收`。不得猜官方账号 handle，不以同名、头像或搜索排名作为官方认证。

## 3. 比赛发现、解析和证据

### 3.1 信息来源优先级

优先官方规则/活动详情；其次已核实官方社交公告、主办/联合主办方公告；第三方汇总只作发现线索，待回到官方规则核实。

保留每条来源的 URL、发布日期、抓取时间、语言、有效期、解析状态和内容哈希。搜索引擎显示“最近抓取”不代表比赛刚发布。页面标题“报名中”也不能覆盖明显的历史截止日期。

发现阶段关注活动列表和新增链接；跟踪阶段重复检查已经收藏/参赛的具体规则页。只监控一张已知活动页无法发现下一届比赛，必须分别实现这两类任务。

无官方来源时可存 `unverified` 线索，但不能纳入“已核实可参赛”统计。用户手工录入不是官方核实，必须保留来源类型。

### 3.2 采集方式

复用 V2 的 RSS、公开网页、官方 API 与获准的浏览器适配器。优先使用可读 HTML、结构化数据和页面现有文本。

动态页面需要浏览器时只作用于选定来源；遇到登录、验证码或限制就停止该来源并提示，不使用账号池、验证码绕过或反检测强化。不要自动读取用户所有浏览器登录态。

规则只有图片时，保存最小必要的原始图片引用与人工核实入口；本轮不把批量 OCR 当默认依赖。图片提取的日期/金额未核实不得驱动准确倒计时。受限页面可由用户粘贴公告正文或上传其有权使用的材料。

外部公告始终是不可信输入：网页中要求运行命令、上传凭证、安装插件等文字不能作为执行指令；LLM 只能提取到既定 Schema，不能调用发布或系统工具。

## 4. 比赛卡片必须包含什么

| 类别 | 字段与要求 |
|---|---|
| 身份 | competition_id、主办/联合主办方、原文标题、中文摘要、届次、赛区、语言、官方详情/报名链接 |
| 状态 | 线索、待核实、即将开放、征集中、已截止、评审中、已公布结果、取消；状态证据独立保存 |
| 时间 | 公告时间、报名开始/截止、作品提交截止、数据统计截止、结果公布时间；每个里程碑分别存原文、年份、时区、精度与 UTC 值 |
| 奖励 | 现金币种、奖池总额、单奖金额、名额、积分、会员、流量扶持；现金与非现金分开；条件奖池/人数门槛/奖励兑付条件单独记录 |
| 参赛资格 | 地区、年龄/身份、个人或团队、是否限会员、是否收费；未明确的为未知，不默认全球/免费 |
| 创作要求 | 题材、必须使用的软件/模型、生成占比、时长、比例、分辨率、语言字幕、水印、发布时间限制、是否允许旧作品/多投 |
| 发布与报名 | 可发布平台、必须的话题/@/声明、是否还需填写表单、作品链接及工程/提示词提交要求 |
| 评审与权利 | 官方评审/平台数据权重，取单平台最佳还是多平台合计，版权/独家/宣传使用条款摘要及原文位置 |
| 用户动作 | 收藏、感兴趣、准备中、已发布待报名、已报名、已获奖/未获奖、忽略；关联内容与发布记录，不替用户做报名动作 |
| 可追溯 | 字段级 source_url、证据定位/短摘录、source_revision、extraction_method、verified_by、verified_at、缺失字段与冲突 |

没有明确单奖现金不能把总奖池当作用户能拿到的钱。奖励有参与人数等触发条件时在卡片正面展示，不能藏在详情末尾。不得计算或承诺中奖概率。

已核查的 Flova 活动样例分别包含有条件启用现金奖、社交发布与表单提交要求，以及多平台只取一个最佳表现帖的规则。[S3] 所以“发现比赛 → 发布作品 → 报名确认 → 数据跟踪”必须是不同状态，不能把发布成功直接等同参赛成功。

国内/国际版、不同届次、不同赛道用独立实体或明确父子关系；同一活动在多个官方渠道宣传可关联来源，但相似名称只给合并建议，不自动删除。

## 5. 截止提醒与规则变化

### 5.1 不能猜的时间

保留原文，转换到工作区显示时区，默认 UTC+08:00。原文有明确时区时采用对应 IANA 时区处理夏令时；只有 PST/PT/CST 等缩写且含义不明时进入待核实。

缺年份、缺日期或缺时区不得根据当前年份/电脑所在地自动补全；缺时刻可显示“某日截止，具体时间未明确”，不给精确小时倒计时。可为日期级期限发提前准备提示，但必须标注日期精度，不暗示当日 23:59 才截止。

不同官方来源冲突时保留候选值，标记 `needs_review`。明确的延期/更正可产生新规则版本；普通转载的发布时间更晚，不自动胜过正式规则。截止状态与“规则页上次成功检查时间”同时显示。

### 5.2 事件与提醒

设计事件：新比赛、正式开放、规则变更、截止临近、延期、取消、结果公布、采集失效。

设计默认提醒档位：截止前 7 天、3 天、1 天、2 小时，可修改或关闭；只有确定的 deadline 才启用精确档位。是否适合参加由用户自己决定，不因自动提醒触发付费或报名。

唯一键至少包含 `(competition_id, milestone_id, deadline_revision, reminder_offset, destination)`。已送达和已读状态入库；延期后撤销旧的待发送提醒，按新版本重算，已发消息保留更正关联。

网页导航、推荐作品、广告和倒计时文本变化不算规则变化；对标题/期限/奖励/资格/创作要求/提交方式等结构化字段做语义差异。保存旧值、新值和证据，不只提示“页面变了”。

首次扫描存基线，历史已截止赛事不当新赛刷屏。对于首次发现且仍可报名的赛事，可单独显示“首次收录”，不要声称刚刚发布。

应用停机时不会发送提醒。恢复后不要补发每个错过档位；若仍有有效期限发一条当前状态提醒，已过期则记录错过窗口。工作区恢复后任务暂停，由用户确认后再运行。本文没有创建 ChatGPT 定时任务。

## 6. 多社交平台账号监控

### 6.1 明确支持范围

首批账号平台：抖音、小红书、B站、YouTube、TikTok、Instagram、X。同平台可以配置多个账号，不能每个平台只留一个 Cookie 槽。

国内公众号/视频号、微博可按相同注册结构后续扩展；Discord 官方公告频道作为可选信息源，不与社交账号数据看板混为一种对象。

| 平台 | 本轮接入方向 | 不得承诺的能力 |
|---|---|---|
| 抖音 | 沿用现有采集适配层，但“账号主页新增作品”须单独验证；自有后台数据用文件或有权限的官方接口 | 关键词搜索成功不等于账号监控成功；粉丝接口本身要求权限和用户授权。[S13] |
| 小红书 | 多账号建档、导入、主页/帖子链接来源；只在来源规则允许且实测通过后启用对应采集 | 未验证时不得展示“全量笔记、所有收藏/曝光实时可读” |
| B站 | 多账号建档、导入、用户作品来源适配与分页验证 | 不用非官方接口存在来证明其稳定性、许可或全量覆盖 |
| YouTube | 优先官方 Data API，频道 uploads playlist 增量读取，绑定稳定 channel/video ID。[S14] | 公开列表不等于自有 Analytics 权限，也不包含所有私人/已删除内容；配额/留存须单独处理 |
| TikTok | 优先已批准应用下的用户授权 Display API，按 scopes 读取授权用户资料与视频。[S15] | 不是输入任意陌生账号就获得其完整视频和后台指标的通用接口 |
| Instagram | 档案/导入先可用；开发时验证官方 API、账号类型、权限和读取范围 | [uncertain] 本次未成功读取 Meta 官方说明，不宣称任意个人账号/竞品 Insights 可用 |
| X | 按官方用户时间线接口与应用实际权限读取帖子。[S16] | 不承诺免费、无限历史或无限频率；启用前展示成本/配额约束 |

所有平台都要有账号档案和来源状态，但“档案可用、人工导入、自动读取新作、读取公开指标、读取后台指标”分别验收；不能用一个绿色“已支持”掩盖差异。

### 6.2 三类角色、两条数据边界

自有账号 owned：用于自己的发布和经营数据。
参考账号 watched：用于选题和公开内容观察。
主办方账号 organizer：本质是经身份核实的观察账号，带 provider 关联，用于发现比赛公告；不新增权限。

同一账号可兼有角色；同一人跨平台账号可由用户确认归入 creator_group，但不能因同名自动合并。外部账号ID为 TEXT；身份与用户名变化分别管理。

监控内容：新作品、原文/标签/发布时间、可取得的点赞评论等指标快照、可比粉丝变化、连续无更新、来源失败。数据来源和截至时间始终可见。

未获取到的指标为 null；采集失败不代表掉粉或没有更新；列表中没找到旧作品不代表已经删除。数据快照/累计/区间口径继承 V2，不以全部累计快照求和。

同账号独立的连接配置、监控频率、游标、基线、错误、预算、暂停状态。不同账号的失败独立；共享同一应用配额时还要有上层预算，不能为每个账号都分配整份额度。

有浏览器会话时按 connection_id 隔离并加锁，不并发使用同一个 profile。使用官方授权优先于 Cookie；不得共享登录态来绕过权限或限额。

### 6.3 官方账号发现链

从 provider 官网的真实链接取得候选账号，记录 `identity_evidence_url`；用户也可添加，但需要确认身份。建立 provider→account→source 关系后，该账号的新作品同时可流入“账号监控”和“比赛线索分类”，只采集一次。

小云雀官网已提供抖音/小红书链接，Flova 已核查活动页包含 X、Instagram、TikTok、YouTube 链接。[S3][S5] 这说明可以做双路来源关联，但不意味着这些平台的数据获取权限已打通。

Discord 仅在服务器/频道授权及所需权限可用时接入官方 bot；消息正文能力受权限/intents影响。[S17] 不使用个人账号 self-bot 或索取用户 token；没有 bot 接入权就保留公开链接/人工导入。

## 7. 与知识回填、参赛作品的关联

闭环：`公告/账号新作 → 证据 → 比赛/参考卡片 → 用户选题 → 内容项目 → 各平台发布 → 报名记录 → 结果与复盘 → 审核后的知识`。

比赛规则作为有届次和生效范围的知识，不直接提升为“这个平台永远要求某模型/时长”。历史赛事可以进案例库，不进入当前可参赛列表。

用户修改提取错误时保存纠错，先作用于这一版本；通用解析规则修改需要明确批准。模型整理失败时保存原始证据并提示，不能把错误字符串写成正式知识。

关联使用 competition_id、content_id、publication_id、submission_id、knowledge_id，不靠标题猜测。发布文案中有比赛话题，只能推断“可能参赛”；有表单回执/用户确认才进入已报名。不同比赛的多投和独家条款分别核查。

可记录参赛后的成本、制作耗时、获奖结果及实际到账/积分到账；奖项公告不等于奖金已到账。付款和兑奖由用户完成，本轮不代付、不自动提交身份证或银行信息。

可选“适合我”筛选：作品类型、时长、使用工具、是否限地区、是否有现金、制作预算、剩余时间。未知资格显示待确认；排序是可解释的个人筛选，不是获奖预测。

在 V2 的 sources/accounts/source_items/observations/jobs/outbox/knowledge 模型上增量添加：

| 实体 | 核心语义 |
|---|---|
| providers / provider_channels | AI平台与其来源/官方账号、身份核实证据；多个渠道不重复采集 |
| competitions / competition_sources | 稳定比赛ID、届次/赛区、来源关联、分类、状态 |
| competition_revisions / field_evidence | 字段旧新版本、证据定位、提取/人工核实信息 |
| competition_milestones / awards | 各类期限与精度；分层奖励、币种、非现金、激活条件 |
| participation_records | 用户参赛状态、内容/发布关联、提交回执引用与结果 |
| deadline_notifications | 版本化提醒、取消/送达/错过状态与幂等键 |
| creator_groups / account_bindings | 用户确认的跨平台主体关系、权限引用；不存秘密 |

公开种子可进 GitHub；用户实际观察名单、资格设置、作品、报名信息和知识属于工作区私有数据。设备凭证仍不打包。

留存和迁移必须受来源条款约束，不能把“可打包”解释为永久保存一切 API 数据。连接器带 `retention_policy_ref, refresh_due_at, delete_after, export_allowed, redistributable`，在导出、恢复和展示时检查。YouTube 官方开发政策对数据使用和存储有专门要求，接入前要按其当前条款落实刷新/删除及用户撤销规则。[S18]

对不允许导出或需要刷新才能使用的数据，包中列出排除项/needs_refresh，保留允许的用户自写笔记和关联信息；不得通过备份恢复绕过已经生效的删除要求。第三方正文只保留允许的最小必要内容，不整站归档。

完整工作区包新增比赛、版本、里程碑、已读与提醒状态、允许保留的账号观察历史。模板包只含公共来源配置、分类和提取规则、提醒模板；不带参赛状态和私人名单。恢复后规则可用，调度暂停；凭证重新授权，待发送提醒按当前期限重算。

## 9. 页面、接口与开发顺序

### 页面

比赛中心：按平台/类型/阶段/奖励/截止筛选；本周截止、待核实、规则变更、我的参赛四个视图。卡片正面显示单奖/奖池区别、限制、来源与上次核查时间。

账号监控：按平台和角色分组、账号多选、独立启停、新作品收件箱、数据截至时间、采集健康。官方账号公告可一键转比赛线索，参考作品可转选题卡。

信息源管理：查看公开种子、添加链接、身份核实、probe、测试解析、最近成功与错误；链接未接通时显式给“人工补录”入口。

设置与迁移：沿用 V2，新增比赛与提醒的打包范围预览，不能把私有账号清单写进公共配置文件。

### 接口

沿用 `/api/workspace/*`，新增 providers、competitions、competition revisions/milestones、participations、deadline notifications；复用 sources、accounts、events、knowledge、packages，不复制一套队列。

保留分页、筛选、服务端验证、事务、版本号和审计。提取/采集是任务，不把长请求阻塞在 Web 主线程。比赛发现和单比赛规则跟踪是不同 job_type。

### 实施顺序

A：沿用 V2 便携底座；预置12家AI平台与7个社交平台档案/能力表；支持手工登记比赛。
B：先做 Flova、Higgsfield、即梦等已知官方页面的提取/变更测试；比赛卡片、期限、差异、去重和本地提醒端到端可用。来源受阻则记录，不伪造网页结果。
C：接 YouTube 官方公开内容读取路径与现有国内平台适配器；验证多账号隔离、基线、二次检查及分页。小云雀官方账号可作为用户确认后的候选验证来源。
D：逐个补齐五家指定平台的活动渠道及其他社交连接器；给出每个来源的测试报告和未覆盖项。不能以海外来源成功代替国内平台验收。
E：知识/参赛关联、导出恢复、费用/配额和留存检查回归。

必须区分 `unit_test_passed / fixture_test_passed / live_fetch_verified / scheduled_cycle_verified`；浏览器搜索本次能读到页面不等于 WorkBuddy 的连接器已实现。

## 10. 新增验收测试

C01 五家指定平台与七家国际平台均可见，无比赛入口的明确待补源，不假装无赛事。
C02 一个主办方在官网和社交平台发布同赛可关联多来源；中外赛区/不同届次不误合并。
C03 普通优惠、推荐有奖、产品更新、历史获奖新闻不会自动成为正在征集的比赛。
C04 奖池/单奖/积分/流量权益和激活条件分别显示，缺失不补现金值。
C05 缺年份、时区、时刻与夏令时边界被正确处理，不产生猜测的精确截止时间。
C06 正式规则和社交公告冲突会阻止自动定论，并显示来源；人工更正有版本和审计。
C07 延期后旧提醒取消，新期限按版本重排；重启/重试不重复通知。
C08 广告、导航和倒计时变化不会触发“规则修改”；时长/资格/奖金变化会产生字段差异。
C09 停机后不刷出所有过期提醒；迁移恢复后任务暂停、已读/已发记录保留。
C10 七个社交平台均支持多账号档案/导入；真正支持的读取能力逐项展示。
C11 合成样例中同平台两个账号互不串数据；单账号授权失效不阻塞另一个，测试报告标注样例。
C12 至少一个官方社交接口与一个国内目标账号分别完成真实读取验证；权限受阻应标未通过，不能只用假数据截图交付。
C13 账号改名仍保留稳定ID，未确认的跨平台同名账号不合并。
C14 首次扫描不把全部历史作品当新作；采集失败不清空历史或把粉丝降到0。
C15 provider官方账号的新帖采集一次，可被比赛分类器与账号收件箱复用。
C16 比赛要求单平台最佳时不把所有参赛帖子互动相加；不把本地统计冒充官方比赛排名。
C17 发帖与报名分开，未有回执/人工确认不标已报名；公告获奖与奖励到账分开。
C18 知识卡保留届次、证据和审核状态，错误提取不会变成永久平台规则。
C19 包中不含Cookie、Token、报名凭证中的秘密；模板不含私人观察账号或参赛状态。
C20 换目录恢复仍能关联比赛、作品、规则和来源；留存过期/不允许导出的数据被正确处理。
C21 真实抓取测试与定时完整周期测试分开，不使用搜索工具回包冒充本机定时器结果。
C22 数据已撤销/到期后，旧备份恢复不会静默重新启用；记录需刷新和删除处理。

最终提交：增量代码、迁移、适配器与公开种子配置、Windows启动说明、自动化/真实来源测试清单、至少一套脱敏或合成迁移样例、界面截图和已实现/受阻清单。禁止把此文档本身计作已实现监控。

## 11. 发给 WorkBuddy 的启动提示词

读取本仓库 `docs/rix-ops-monitoring-v2` 分支中的 `docs/RIX_PORTABLE_OPS_V2.md` 和 `docs/RIX_CONTEST_SOCIAL_V2_1.md`，以 V2.1 为新增范围、V2 为底座，在实际最新本地代码上增量实现。

重点是“AI平台比赛监控＋多社交平台多账号监控＋知识回填＋可迁移工作区”。优先平台为 OiiOii、即梦、Flova、Liblib、小云雀，并预置本文的国际平台名单。社交平台包括抖音、小红书、B站、YouTube、TikTok、Instagram和X。

先核查代码、权限、依赖和来源，用新实现分支保护本地改动，不回退旧版本、不覆盖main、不盲目推送。不要创建新的SaaS或只做静态页面。沿用Flask和SQLite，复用现有导入/任务/知识/Loop结构。

先打通“来源→比赛卡/账号新作→版本和提醒→关联内容/知识→导出→新目录恢复”。每个来源单独展示身份、解析、权限、定时测试状态；不得猜活动日期、奖金和官方账号，不得绕过平台限制。缺失指标为null，累积快照不相加，私有数据与凭证不进GitHub。

真正编写代码、迁移、测试和启动脚本；按阶段报告已完成、未验证、被权限阻塞的具体项。没有运行验证的连接器不得标已接通。报名、公开发布、付费和远程推送必须另有明确授权。
