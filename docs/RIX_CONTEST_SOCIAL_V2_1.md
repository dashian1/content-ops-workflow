# RIX 工作台 V2.1：AI 平台比赛监控＋多社交平台账号监控

日期：2026-10-12。状态：增量开发任务书，尚非已运行的监控服务。
仓库：`dashian1/content-ops-workflow`。
底座文档：同分支 `docs/RIX_PORTABLE_OPS_V2.md`。

> 目标：在一个工作台发现值得参加的 AI 创作比赛，跟踪截止时间、奖励与规则，同时监控多个社交平台的自有账号、参考创作者及主办方官方账号。
>
> 本文新增比赛与账号监控范围；保留 V2 的 Flask、SQLite、独立工作区、知识审核、代码/数据/凭证分离、打包恢复和测试要求。不是新建 SaaS，不把数据绑定公司电脑。

除明确标注引用的事实外，字段、界面、优先级、提醒时间和验收条目均为本项目设计，并非平台官方标准。公开页面可读取，不代表已经获准自动采集；公开来源已找到，也不代表 WorkBuddy 的连接器已实现。

本轮范围：AI平台比赛监控、多社交平台多账号监控、知识回填、可迁移工作区。先完成下面的最小闭环，再逐家扩展连接器：

`来源 → 比赛卡/账号新作品 → 去重与版本 → 提醒/事件 → 关联内容与知识 → 打包 → 新目录恢复`

真实编写代码、迁移、测试与 Windows 启动说明。所有连接器分别报告已实现、夹具测试通过、真实读取通过、完整定时周期通过；未实测不得标记已接通。权限受阻时继续完成独立模块，交付具体错误和人工导入入口，不伪造成功。

## 1. 模块和对象必须分开

| 模块 | 对象 | 输出 |
|---|---|---|
| 比赛中心 | 比赛、创作挑战、作品征集、创作者激励 | 比赛卡片、规则、截止提醒、变更历史、参赛进度 |
| 账号监控 | 同平台多个账号、跨平台多个账号 | 新作品、可获得的公开或已授权指标、来源健康、参考内容 |
| 知识回填 | 比赛规则、参考作品、个人制作与参赛复盘 | 证据、草稿、已审核知识，供以后选题和创作复用 |

`provider` 是 OiiOii/Flova 等 AI 平台；`social_platform` 是抖音/YouTube 等传播平台；`account` 是具体账号；`source` 是实际读取的网页、列表、频道或接口。不能用一个 platform 字段混装这四种对象。

每家 AI 平台可以同时关联官网活动页、正式公告及已核实的官方社交账号。同一帖子采集一次，账号监控和比赛分类器共同使用，不重复请求。

将比赛、抽奖、邀请返利、普通折扣、产品更新、获奖回顾、创作者招募分别分类。默认聚焦 AI 图片/海报、视频、短片、动画、广告、MV；一般编程赛默认不进入视觉创作比赛推荐。

## 3. 比赛发现与规则跟踪

同时实现两种任务：`discover_competitions` 读取活动列表/官方新公告发现新赛事；`track_competition_rules` 重新检查某场比赛的规则。只盯一张旧活动页不能发现下一届。

信息优先级：正式官方规则/活动详情 → 已核实的主办方与联合主办方公告 → 第三方线索。第三方可帮助发现，但须回到官方来源核实；未核实线索可存档，不进入“已核实可参赛”统计。

每个来源保留原文标题、链接、语言、原始发布时间、首次观察时间、上次成功读取时间、内容哈希和解析状态。搜索引擎抓取时间不是比赛发布时间；“报名中”标题不能覆盖明显的历史期限。

复用 V2 的官方 API、RSS、允许采集的公开页面及受控浏览器适配器。先取页面文本和结构化数据。规则只有图片时提供人工核实入口，图中金额/日期未核实不驱动精确提醒；不默认批量 OCR。

遇登录、验证码、权限限制或限流时停止或有界退避并显示原因。不实现验证码破解、账号池、反检测强化、绕过访问控制。浏览器会话按 connection_id 隔离，不自动读取用户全部登录态。

外部公告作为不可信数据处理。网页要求运行代码、传凭证等内容不成为执行指令；模型只能按固定 Schema 提取，不允许其据网页内容调用系统、发布或付款工具。

## 5. 时间、变更、提醒

保留原文并以工作区时区展示，默认 UTC+08:00。明确地区时区用 IANA 时区处理夏令时；PT/PST/CST 等缩写含义不明就待核实。不依据电脑所在地猜时区，不依据当前年补缺失年份。

缺时刻可显示“某日截止，具体时间未明确”，不给小时级倒计时，也不默认当天23:59。日期级期限允许提前准备提示，但要标明精度。报名截止、交片截止、数据统计截止是不同 milestone。

默认可配置提醒档位：截止前7天、3天、1天、2小时。只有可确定期限才启用精确档位；所有提醒可停用。事件还包括新赛事、开放、延期、取消、结果、规则变更和采集失效。

规则变更对结构化字段比较；导航、广告、推荐作品和跳动倒计时不触发规则告警。保存旧值、新值和来源。官方明确更正/延期创建新 revision；较晚转载不自动胜过正式规则，冲突进入 needs_review。

提醒唯一键至少 `(competition_id, milestone_id, deadline_revision, offset, destination)`。延期后取消旧待发提醒，按新版本重算；已发消息保留更正关系。重试、重启和迁移不得重复刷屏。

首次扫描建基线，历史已截止活动不当新赛通知。首次收录且仍可报名的赛事标“首次收录”，不声称刚刚发布。停机期间不发送提醒，恢复后合并处理错过窗口，不补发每个档位。

通知先进入本地工作台；飞书/Webhook 为可选出口，外部失败独立重试。导入工作区后调度默认暂停，用户确认再运行。本规格没有创建 ChatGPT 定时任务，也不代表 GitHub 会代替本机常驻执行。

| X | 按官方用户帖子接口及实际应用权限接入。[S16] | 不承诺免费、无限频率或无限历史；启用前核对成本和额度 |

账号档案、人工导入、自动新作品、公开指标、后台指标分别验收。没有权限的指标为 null；不能虚构后台数据。

### 6.1 角色与身份

owned：自己的运营账号；watched：参考创作者；organizer：关联 AI 平台、已核实身份的主办方观察账号，不增加权限。同一账号可兼有角色；参考账号不进入自己的经营数据合计。

跨平台同名不能自动合并；用户可确认 creator_group。平台稳定 ID 用 TEXT；账号改名更新别名不丢历史。每个授权连接独立；共享应用额度还要全局预算，不能每个账号都用整份配额。

有浏览器 profile 时按 connection_id 隔离并加锁，不并发使用同一 profile，不共享登录态绕权限。官方授权优先于 Cookie。公众号/视频号、微博可按注册结构扩展；Discord公告频道是可选信息源而非同类账号后台指标，需官方bot与频道权限，不用个人 self-bot。[S17]

### 6.2 监控事件与数据

支持新作品、标题/标签/原发布时间、可取得的互动快照、可比粉丝变化、长期未观察到更新、连接失效。始终显示 observed_at 与来源。

先建基线，后续增量才报新作。抓取不成功不表示没有更新，更不能清空数据或将粉丝置零。未见旧作品只标“本次未观察到”，不当删除。累计快照取可比值，不能把多次累计相加；增量标明观察窗口，不猜小时增速。

官方账号发现链：provider官网链接 → identity_evidence_url → account → source。小云雀官网确有抖音/小红书链接；已读取的Flova活动页有其国际社交账号链接。[S3][S5] 这只支持来源关联设计，不证明各平台采集权限已经接通。

## 7. 参赛与知识回填

闭环：公告/账号新作 → 证据 → 比赛或参考卡 → 用户选题 → 内容项目 → 各平台发布 → 报名记录 → 结果复盘 → 审核知识。

使用 competition_id、content_id、publication_id、submission_id、knowledge_id 关联，不靠标题或话题猜测。“有比赛话题”最多提示可能参赛，表单回执或用户确认后才标已报名。

继承 V2 的 evidence/draft/approved 三层。比赛规则带届次、有效范围、revision与证据，不能上升为永久平台规则。模型失败不回填报错文本；人工纠错先作用当前来源版本，通用解析规则需另行批准。

知识本地保存成功后再投递可选 Obsidian/飞书，以稳定ID和revision幂等更新，不重复新建笔记、不覆盖人工备注。外部服务故障不妨碍本地保存和打包。

可记录制作耗时、积分/现金成本、结果与实际奖励到账；不代用户付款、报名、兑奖、公开发帖或提交身份证/银行信息。多投、独家和版权限制逐赛核实。

提供可解释的“适合我”筛选：作品类型、时长、工具、地区限制、现金/积分、预算、剩余时间。未知资格显示待确认；这是个人筛选，不是获奖预测。

完整包增加比赛、规则历史、里程碑、提醒已读/已发状态、允许携带的账号历史。模板包仅带公共源配置、筛选/提醒规则和审核过的通用知识，不带真实名单或参赛信息。仍用相对路径、稳定ID、SQLite一致性备份；恢复后授权需重绑，任务暂停，提醒按当前期限重算。

采集数据留存与导出受来源条款约束，不能因备份功能而永久保存一切。连接器记录 `retention_policy_ref, refresh_due_at, delete_after, export_allowed, redistributable`；导出、恢复、展示都检查。YouTube 官方政策对 API 数据存储、使用有专门要求，接入前落实当前刷新、删除和撤销规则。[S18]

不允许导出的数据列入排除清单，需要重新获取的标 needs_refresh；保留允许的用户自写笔记/关联。旧备份恢复不能静默重启已撤销或到期数据的使用。仅保存被允许且必要的第三方内容，不整站归档。

## 9. 页面、接口、实施顺序

## 10. 新增验收测试（继承V2全部测试）

C01 五家指定与七家国际平台均可见；无列表显示待补源，不报无比赛。
C02 同赛多来源正确关联；国内/国际版、不同届次不误合并。
C03 优惠/返利/产品更新/历史获奖不误判为正在征集。

C05 缺年份/时区/时刻和夏令时边界正确处理，无猜测精确期限。

C07 延期取消旧提醒并重排，重启/重试不重复通知。
C08 导航/广告/倒计时不误报；资格/奖金/时长等变化有字段差异。
C09 停机恢复不补发全部档位；迁移保留历史，调度默认暂停。
C10 七种社交平台均支持多账号档案/导入，自动能力逐项展示。
C11 同平台两个账号不串数据，单账号授权失败不阻塞另一个。
C12 一个官方社交接口和一个国内账号分别真实读取验证；受阻标未通过，不能用假数据截图代替。
C13 稳定ID保留改名历史；跨平台同名未确认不合并。
C14 首次扫描建基线；失败不清历史、不将指标置零。
C15 官方新帖采集一次，可被比赛分类和账号收件箱复用。
C16 单平台最佳规则不被多平台合计替代，本地分析不冒充官方排名。
C17 发布/报名分开、获奖/到账分开，无确认不升级状态。
C18 知识带届次、证据、审核状态，错误提取不成为永久规则。
C19 工作区包无Token/Cookie等秘密；模板无私人名单/参赛状态。
C20 新目录恢复仍关联比赛/作品/知识/来源，处理不允许导出项。
C21 真实抓取与完整定时周期独立测试；搜索结果不冒充本机定时器运行。
C22 已撤销/过期数据不因旧备份恢复而静默重新启用，按政策刷新/删除。
