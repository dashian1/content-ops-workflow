# RIX 个人创作运营台｜WorkBuddy 续开发与独立化任务书 V3

日期：2026-10-12。V3 是任务书版本，不是已发布的软件版本。

> **重要前提：用户明确告知，WorkBuddy 刚才已经完成了一轮开发。请先接管这轮实际成果，不要当成从零开始，不要重建已经可用且可合法复用的模块。**
>
> **本次任务是“现状核查 → 资产分类 → 保留可复用成果 → 对受限部分独立实现 → 补齐闭环 → 真实验收”，不是把旧项目拼接、改名后宣布变成个人资产。**

本文件取代旧任务书关于“必须以原公司仓库继续开发”“必须固定使用 Flask”“整个工作台仍只有文档”的默认假设。V1/V2/V2.1 的产品要求可以查阅，但遇到冲突以本文件为准；旧文档不能证明当前本地实现进度。本文可单独执行，不要求导入旧代码。

## 2. 第一项任务：接管已经开发的成果

先在用户已经指定的当前目录内检查，不到其他公司目录寻找可搬走的资料。

读取本轮 WorkBuddy 会话、最近产物、项目说明、启动脚本、Git 状态、依赖、路由/命令、数据结构、测试与运行记录。记录当前 HEAD、分支、工作目录、未提交/未跟踪文件，但日志和报告不要输出密钥或私有数据。

禁止执行 `reset --hard`、`clean -fd`、删除目录、覆盖数据库、直接切分支丢改动、重装整个环境或自动改远程地址。需要建立检查点时，在当前有权使用的位置保留安全副本/补丁；不把原公司目录整体复制到个人项目。

先输出本地 `docs/CURRENT_STATE.md`：

| 功能 | 实际入口/文件 | 是否有实现 | 当前验证方式与结果 | 来源/依赖 | 下一步 |
|---|---|---|---|---|---|
| 工作区、账号、导入、比赛、来源采集、监控、知识、打包、制作接口 | 逐项填真实定位 | 有/无/部分 | 未测/离线/真实读取/端到端 | 自有/授权/第三方/受限/待确认 | 保留/修复/重写/补做 |

不要只凭 README、截图、HTTP 200 或函数名称填“通过”。先跑不触发外网、付费或真实业务写入的启动检查与离线回归；模型、生图、发布、授权流程分别标记。

若本机已有实现而 GitHub 没有，记为“本地已实现、尚未核实远程同步”，不要覆盖成本仓库旧版本。找不到当前实现时，记录已检查的具体范围，不把旧公司仓库当作缺省替代。

## 3. 资产复用规则：保留成果不等于全部搬走

建立私有的资产清单，逐项记录 `asset_id、来源、文件/组件、内容类型、使用权限证据、依赖、处理决定、审核状态`。详细路径与授权材料不上传公共仓库；公共报告只留脱敏状态。

| 分类 | 决定 |
|---|---|
| 已确认可用于个人项目的独立实现 | 保留，补测试；不因换产品名重写 |
| 有明确许可证或授权的组件 | 按许可范围复用，保留署名、许可、修改说明及必要义务 |
| WorkBuddy 新增但依赖公司代码/私有数据 | 保留在原有授权位置；不得自动视为独立个人代码，拆清依赖后决定重新实现或取得许可 |
| 公司专有代码、业务提示词、客户资料、私有知识和运营数据 | 无相应权限不复制、不打包、不上传到个人项目 |
| 来源或权限不明 | 标记 HOLD；不进入个人构建产物，独立实现所需通用能力 |

依据公开产品行为、用户亲自提出的需求、官方接口说明独立实现，不把公司私有实现逐行翻译、改变量名或经模型改写后当作新的个人资产。测试样例重新使用合成数据或获准的公开/个人数据，不能把公司测试库顺手搬过来。

公开可读并不自动等于可自由复制再分发；第三方组件需核查实际许可证。[S1] 本项目不出具“保证无权属风险”的结论。

## 4. 新产品的范围：整合能力，不拼接仓库

暂名 **RIX 创作运营台**；个人仓库建议名 `rix-creator-workbench`，名称可调整。

### 4.1 产品主线

```text
比赛/平台公告/参考账号/个人收藏
                  ↓
        统一来源库、去重和证据
                  ↓
      今日行动台：挑比赛、挑选题
                  ↓
    内容项目：Brief、提示词、素材、封面
                  ↓
      分平台发布包、参赛提交检查
                  ↓
      发布记录、指标、成本与结果
                  ↓
     人工确认后的案例与知识回填
```

参考以往工具的“定时采集、数据清洗、任务执行、版本管理、经验回填”等通用能力，不继承公司特定商品、人群、营销打法、术语、模板或商业数据。默认面向个人 AI 视觉创作者，不把选题自动改写为产品带货。

### 4.2 功能范围与优先级

| 功能 | 本轮优先完成 | 后续逐项扩展 |
|---|---|---|
| 多账号与数据 | 同平台多账号、owned/watched/organizer 分角色、栏目、作品与发布、文件导入、指标快照 | 获授权的后台接口、更多平台字段 |
| 比赛与来源 | 来源档案、规则与证据、期限、变更、去重、至少一条真实发现/跟踪路径 | 更多站点适配、更多征集与合作机会 |
| 今日行动台 | 手工规则筛选、用户选择、最多突出 3 件当前行动，推荐理由可见 | 个性化排序；不做获奖概率预测 |
| 创作任务包 | 规则摘要、栏目要求、参考、提示词、素材清单、验收清单导出 | 用个人授权接一个生图接口与固定封面模板 |
| 制作与版本 | 已有可复用实现优先保留；先测试图再批量、单项返修、记录实际模型与参数 | 视频生产和更复杂编辑；暂不做多模型无限 Agent |
| 数据与知识回填 | 来源→草稿→已确认知识；稳定 ID、版本、结果图片与提示词绑定 | 可选 Obsidian/飞书出口；不作为唯一存储 |
| 便携与复用 | 个人工作区包、模板包、恢复自检、路径可迁移 | 可选成熟加密封装和常驻采集端 |

不要把已实现的生图/封面功能删除，仅因它排在后续；来源与权限通过后照常保留。尚未实现时先打通任务包交接，不让内容生产能力缺口阻塞数据与监控验收。

## 5. 数据与执行约束

账号档案不等于授权；观察账号和主办方账号不获得自有后台权限。参考数据不计入个人经营汇总。跨平台同名账号由用户确认归组，不自动合并。

一条内容可关联多个发布记录，各发布记录绑定账号与平台作品 ID。平台 ID 为字符串；缺失指标为 null，真实 0 保留；累计快照不相加。区分发布时间、观测时间与导入时间，保留原口径、来源、原始值和人工修订。

来源采集有超时、有限重试、暂停/取消、限流处理、游标、基线和 coverage。首次抓取的历史条目不冒充新发布；失败不解释为“无更新”。同一来源多个用途只采集一次。遵守平台权限，不做验证码破解、账号池或反检测强化。

比赛保存报名/交片/数据统计等不同期限；保留年份、时区、精度和原文。未知日期不猜，奖池不冒充单人奖金，现金和积分分开。规则延期后取消旧待发提醒，去重键包含期限版本。发帖、报名、获奖、到账分开记录。

UI、CLI 和后台执行器共用服务层，避免每个入口再写一套规则。已有可靠执行器可保留；只有状态图没有执行代码的不算执行器。付费生成要有预算和幂等记录，结果不明时先查任务状态，不能重复扣费。

## 6. 技术路线：以本地事实决定，不强制重写技术栈

先审核 WorkBuddy 当前使用的框架、数据库和服务边界。已有独立可用的前端/后端就沿用，不因旧文档写 Flask 就强制迁移，也不因为参考系统使用 ThreadingHTTPServer 就强制换成它。

SQLite＋本地文件仍是单人便携版的默认建议；已有其他持久化实现时先验证能否独立部署和一致导出，只有不能满足目标才迁移。Python 提供 SQLite 接口与一致性备份能力。[S2]

不以 n8n、Redis、固定服务器、新前端框架或付费 API 为必需前提。无模型 Key 时，应仍能建档、导入、查询、管理来源、记录比赛、手工保存知识、导出恢复。自动写提示词或生图按已配置的个人凭证启用。

## 7. 个人工作区与迁移

```text
个人项目代码/             # 仅通过来源审核的代码、说明、迁移、合成测试
个人工作区/
  workspace.json
  db/
  assets/
  sources/
  knowledge/
  templates/
  imports/
本机私有配置/             # Key、浏览器登录态、设备路径，不随工作区携带
```

代码、数据、设备配置分离；个人工作区不放公司产品库的符号链接或绝对路径引用。新工作区启动不能自动读取旧目录、旧数据库或旧账号名单。只导入用户选择且确认有权携带的个人资料。

完整包带个人账号档案、允许保留的数据、来源、比赛、游标、规则、知识和选择的附件；模板包只带获准复用的通用规则，不带私人账号历史、名单、参赛信息或秘密。第三方内容的留存与导出仍受其使用条件约束。

导出冻结相关写入，生成数据库一致性快照，连同知识/附件一起校验；manifest 记录版本、文件哈希、数量、排除项、缺失项和需重新授权项。不能只复制正在使用的数据库文件，也不能把生成 ZIP 当作恢复成功。[S2]

恢复默认进入新目录，不覆盖现有工作区。检查解压大小、路径穿越、校验和、schema 和资源引用；不执行包内脚本。保留业务 ID，清除设备锁，任务暂停，凭证重新绑定。旧实例应停止；不承诺离线副本之间实时同步。

普通 ZIP 明确未加密。依赖通过锁定清单在新设备安装，不能把复制 Python 虚拟环境当可靠迁移；官方说明虚拟环境通常不可携带，应重建。[S3]

个人项目从公司设备迁出仍以有权使用、符合设备和资料管理要求为前提。不得静默上传公司目录、自动删除历史、隐藏操作记录或更改设备安全设置。

## 8. 本轮差量开发顺序

1. **接管与基线**：记录当前实现、来源和测试，不修改业务数据，不凭远程旧代码推断本地进度。
2. **建立独立边界**：可独立复用模块保留；受限模块不带入个人产物。已有个人项目则继续；混合项目则在独立目录按审核结果迁移/重写。
3. **修复与补齐**：只处理真实缺口、失败测试和受限依赖；工作区/账号/导入/来源/监控优先，避免重复造轮子。
4. **行动与制作交接**：把信息转成内容任务包；已有生成和封面功能按权限测试后保留并串接。
5. **真实验证与迁移**：单个比赛来源＋单个社交账号两轮读取、知识保存、导出到新目录恢复。
6. **逐步扩大覆盖**：在稳定闭环之上增加其他连接器；未支持平台仍可建档、导入和查看受阻原因。

每一步先给简短现状与差量，再实际修改和测试。非关键选项使用现有合适默认值，不反复询问；需要外部授权、删除、付费、公开发布或权属确认的动作单独暂停，其他独立工作继续。
